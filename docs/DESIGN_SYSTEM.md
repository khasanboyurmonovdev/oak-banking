DESIGN SYSTEM — Oak Banking

Design Vision

Oak Banking should feel like a premium, modern business banking product.

The design should communicate:

Trust
Financial clarity
Sophistication
Precision
Calm confidence
Modern technology

The product should feel thoughtfully designed, not assembled from a generic dashboard template.

Design References

Use Mercury, Slash, Ramp, and Linear as references for:

Product quality
Visual hierarchy
Information density
Interaction patterns
Typography
Navigation
Component consistency

These products are references only.

Do not reproduce their exact layouts, branding, proprietary assets, or visual identity.

The final design must be original.

Visual Direction

Primary Direction

A refined, light-theme fintech dashboard with a distinctive deep-green brand identity.

The visual language should combine:

Warm off-white surfaces
Deep forest green
Restrained mint accents
Dark, readable typography
Fine neutral borders
Carefully controlled shadows
Generous whitespace
Compact, well-organized financial information

The result should feel premium, trustworthy, and professional.

Avoid

Generic AI-generated dashboard aesthetics.
Excessive gradients.
Glassmorphism everywhere.
Excessive rounded cards.
Overly colorful charts.
Huge empty areas.
Excessively large headings.
Excessive decorative icons.
Random visual effects.
Inconsistent border radii.
Unnecessary animations.
Too many cards competing for attention.

The design must prioritize usability and financial clarity.

Typography

Use a modern, highly readable sans-serif typeface.

Preferred font:

Inter

Alternative:

Geist

Use one primary font family consistently.

Typography Hierarchy

Page Title

Approximately 24–30px
Semibold
Tight but readable line height

Section Heading

Approximately 15–18px
Semibold

Body

Approximately 13–15px
Regular

Supporting Text

Approximately 12–13px
Muted

Financial Metrics

Approximately 26–36px
Medium or semibold
Tabular numerals where appropriate

Avoid excessive font-size variation.

Typography should create hierarchy through size, weight, and spacing rather than decoration.

Layout

Desktop

Use a persistent left sidebar and a main content area.

Suggested layout:

Sidebar width: approximately 224–248px
Main content: flexible
Main content max width: approximately 1440px
Page padding: approximately 28–36px
Consistent spacing between sections

The layout should remain comfortable on standard laptop screens.

Tablet

Reduce sidebar width or use a collapsible navigation.
Preserve the most important financial information.
Avoid unnecessary horizontal scrolling.

Mobile

Use compact navigation.
Consider a bottom navigation bar or a drawer.
Stack dashboard sections vertically.
Adapt tables into readable transaction lists.
Keep financial metrics visible and understandable.
Make interactive controls touch-friendly.

Avoid simply shrinking the desktop design.

Border Radius

Use a restrained radius system.

Suggested values:

Small controls: 6px
Inputs and buttons: 8px
Standard containers: 10–12px
Larger surfaces: 14–16px
Pills: fully rounded

Avoid making every element excessively rounded.

Shadows and Borders

Prefer subtle borders over heavy shadows.

Use shadows selectively for:

Dropdowns
Popovers
Modals
Floating elements
Drawers

Standard cards should generally use:

White surface
Fine neutral border
Minimal or no shadow

The interface should feel crisp and structured.

Dashboard Composition

The Overview page should have a clear hierarchy.

Suggested order:

Page header
Account summary
Cash flow visualization
Account overview
Recent transactions
Supporting financial insights

The precise layout may be adjusted based on viewport size and the final design.

Account Summary

Present the primary balance prominently.

Secondary metrics should be visually subordinate.

Do not make all metrics equally prominent.

Charts

Use a restrained color palette.

Charts should prioritize readability over decoration.

Use:

Clear axes
Meaningful labels
Interactive tooltips
Consistent chart colors
Useful legends
Responsive sizing

Avoid excessive gridlines and unnecessary chart decorations.

Transaction Lists

Transactions should be easy to scan.

Use:

Clear merchant names
Secondary descriptions
Consistent date formatting
Aligned amounts
Clear status labels
Subtle row separators
Appropriate hover states

Amounts should be right-aligned on desktop.

Component Styling

Buttons

Primary buttons:

Deep-green background
White text
Clear action label

Secondary buttons:

Neutral background or outline
Dark text

Destructive buttons:

Clear danger styling

All buttons should have:

Hover states
Focus states
Disabled states
Appropriate loading states when relevant

Inputs

Inputs should have:

Clear labels
Consistent heights
Visible focus states
Appropriate validation feedback
Readable placeholder text

Avoid relying only on placeholders for labels.

Cards

Use cards when they provide meaningful grouping.

Do not place every small piece of information in a separate card.

Status Badges

Use restrained semantic styling.

Examples:

Completed
Pending
Failed
Frozen
Active

Status badges should be small and readable.

Modals and Drawers

Use them for contextual interactions such as:

Transaction details
Transfer confirmation
Account details
Card details

Maintain a clear hierarchy and avoid oversized modal layouts.

Icons

Use Lucide icons consistently.

Guidelines:

Use icons that clearly communicate their purpose.
Prefer consistent sizes.
Avoid unnecessary icons.
Do not mix icon styles.
Use decorative icons sparingly.

Icons must support usability, not replace meaningful text labels.

Interaction Design

Every interaction should feel deliberate.

Use:

Clear hover states
Visible focus states
Subtle transitions
Appropriate feedback
Consistent modal behavior
Predictable navigation
Clear confirmation for important actions

Avoid unnecessary animation.

Transitions should generally be subtle and brief.

Respect reduced-motion preferences where practical.

Responsive Design

The application must work across:

Desktop
Laptop
Tablet
Mobile

Responsive behavior should be intentionally designed.

Pay special attention to:

Sidebar behavior
Dashboard grids
Financial charts
Transaction tables
Filter controls
Modals
Forms

Avoid horizontal overflow.

Accessibility

Follow practical accessibility principles.

Use semantic HTML.
Ensure keyboard navigation.
Provide visible focus indicators.
Maintain readable contrast.
Use labels for form controls.
Use accessible button names.
Provide appropriate accessible descriptions for charts.
Do not communicate status through color alone.
Ensure dialogs have appropriate accessibility behavior.
Design Quality Standard

The final application should be visually credible as a modern fintech product.

Before considering a page complete, evaluate:

Is the hierarchy clear?
Is the financial information easy to understand?
Does the page feel balanced?
Are spacing and alignment consistent?
Are interactions visually clear?
Does the design work on smaller screens?
Is the visual treatment original?
Does anything look generic, unfinished, or unnecessary?

If the answer reveals a weakness, improve the design before adding more features.

Implementation Guidance

Use the design system consistently across the application.

Prefer centralized design tokens where appropriate.

Do not introduce a new visual style for individual pages without a clear reason.

The design system should evolve only when the change improves the overall product.
